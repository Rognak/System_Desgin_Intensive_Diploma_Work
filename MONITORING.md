# Мониторинг

## Инструменты

- **Prometheus** — собирает метрики приложений и инфраструктуры.
- **Grafana** — дашборды по RPS, задержкам, ошибкам, базам данных и очередям.
- **Alertmanager** — отправляет уведомления при срабатывании алертов (например, в Telegram или Slack).
- **Elasticsearch + Kibana** — централизованные структурированные логи; в каждом запросе сохраняем `request_id`, `service`, `status`, `duration`.
- **OpenTelemetry + Jaeger/Tempo** — трассировка запроса через API Gateway → сервисы → хранилища для поиска медленных участков.

## Что отслеживаем

| Компонент | Основные показатели |
|---|---|
| **API Gateway / Search / Feed / Product** | RPS, доля HTTP 5xx, p95/p99 задержки ответов, количество HTTP 429 (Rate Limiter), срабатывания Circuit Breaker |
| **PostgreSQL** | Доступность primary, загрузка CPU/диска, активные соединения, медленные запросы, задержка репликации, использование WAL |
| **Redis** | Доступность, latency, cache hit rate, использование памяти, `evicted_keys`, промахи при чтении персональной ленты |
| **Kafka** | Consumer lag по группам, количество сообщений, ошибки producers/consumers, состояние брокеров и партиций |
| **Debezium / Kafka Connect** | Состояние коннекторов, ошибки, задержка передачи изменений из PostgreSQL в Kafka |
| **Elasticsearch** | Состояние кластера, latency поиска, ошибки запросов, скорость индексации, задержка появления новых объявлений в поиске |
| **ClickHouse** | Доступность, длительность запросов, скорость загрузки событий, ошибки вставки, отставание аналитических данных |
| **FeedWorker** | Длительность и ошибки пересчёта, время последнего успешного запуска, количество пересчитанных пользователей |
| **S3 / CDN** | Ошибки загрузки фото, ошибки отдачи изображений, задержка загрузки, CDN cache hit ratio, исходящий трафик |

## Алерты по требованиям

1. **Доступность ниже 99,9%** — отслеживаем успешность запросов к публичному API и долю времени недоступности. Отдельно оповещаем о росте 5xx и отказе критичных компонентов.
2. **Объявление не появилось в поиске за 60 секунд** — измеряем сквозную задержку от успешного создания объявления до его появления в поисковой выдаче. Проверяем цепочку PostgreSQL → Debezium → Kafka → Elasticsearch, включая обновление поискового индекса.
3. **Рост задержек API** — алерт при существенном ухудшении p95/p99 относительно обычных значений (конкретные пороги задаём после нагрузочного тестирования).
4. **Отставание данных** — алерт при росте Kafka consumer lag, задержки Debezium или репликации PostgreSQL.
5. **Проблемы с персональной лентой** — алерт, если FeedWorker долго не завершал пересчёт или резко выросли промахи в Redis.
6. **Перегрузка** — алерт на высокую загрузку CPU/памяти/диска, исчерпание соединений и массовые HTTP 429 либо открытие Circuit Breaker.
